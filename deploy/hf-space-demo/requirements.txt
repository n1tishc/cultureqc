# ZeroGPU accepts a fixed set of torch builds: 2.8.0, 2.9.1, 2.10.0, 2.11.0 (CUDA
# wheels only). This is pinned exactly rather than lower-bounded like
# hf-space/requirements.txt — a resolver picking anything outside that set fails
# ZeroGPU allocation outright, so it is not something to leave to chance. No
# --extra-index-url here: the plain PyPI wheel already ships CUDA support, and
# is a no-op on CPU (torch.cuda.is_available() just returns False locally).
torch==2.9.1
torchvision==0.24.1

# Deliberately not listing gradio here: this is a Gradio-SDK Space, so
# `sdk_version` in README.md's frontmatter already pins a matched
# gradio+gradio_client pair in the base image. Adding an unpinned `gradio`
# constraint here let pip upgrade gradio to a newer release than the
# preinstalled gradio_client on a real deploy, and the two diverged enough to
# break the server's own /info schema endpoint (breaks gradio_client.predict()
# and the "Use via API" tab, though not the interactive Blocks UI). Bump the
# gradio version by bumping sdk_version instead, so both move together.
